## 接口变化

- B03 新输出 `quality_batch_v2`；B04 仍可读取旧的无诊断异常 v1 交接文件。带诊断错误的记录禁止标记为 kept。
- `diagnostic_errors` 是阶段名到异常文本的映射。已有拒绝证据时，记录同时具有 `status=rejected` 和诊断错误；B03 与 B04 都禁止该条源删除。其余无诊断错误的明确拒绝条仍可按 `run` 模式处置。
- `kept_files + rejected_files + error_files = episodes`。`failed_episodes` 表示输入或诊断执行错误的并集，可以与 rejected 重叠；平台不要再把它直接当作第三个互斥质量类别。
- B04 新增 `execution_status` 表示整个运行是否成功；`delivery_status` 仅描述合格 MCAP 副本交付，复制完成后删除出错时前者 failed、后者 complete 是正确结果。
- `deletion_sync_failed_files` 表示已解除链接但目录同步失败的数量；`deletion_unknown_files` 表示尝试删除却不能确认结果的数量。`deleted_files` 仅统计已确认解除链接，不能代表断电后的持久性。主错误与次级关闭错误均保留。

详细字段和调用方式见 [OPERATOR_IO.md](OPERATOR_IO.md)。四个注册 ID 和串联顺序不变；旧输出目录不能继续复用，应使用新目录。`quality` 保留全部源文件并输出合格副本，`run` 才执行符合资格的拒绝源删除。

## 验收边界

1. 15 项真实引擎及 ABC 集成测试因上游缺失而跳过，真实 S1–S4 数值、ABC 时间轴适配及多进程运行仍由同事验证；本机通过不等同于引擎联调完成。
2. CRC 检查遵守 MCAP 可省略校验和的语义，零 CRC 不强制拒绝；无校验和的内容无法据此证明未被修改。不检查视频像素，不声称校验所有可选索引与消息的语义一致性。
3. 完整性扫描增加 I/O 和解压开销；解压大小受记录上限约束，内存按单条记录 / 单块而非整个文件使用，真实大文件吞吐仍需实测。
4. B02→B03 的引擎统计对象仍在进程内传递，平台跨进程的数据端口尚需接入；B03→B04 已支持同一文件系统下落盘重载。
