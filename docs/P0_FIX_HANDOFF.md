## 范围与算子职责

本次修复经反例确认的两个 P0：空夹爪消息导致缺测漏检、空状态消息导致质量行时间戳错位。按平台场景，本次不扩展处理“统计成员中途变化”和“上游版本变化导致缓存失效”。没有改变隔帧采样、S1–S4 阈值、整条拒绝或删除策略，没有新增第四个算子。

| 算子 | 本次职责与修改 |
|---|---|
| B01 格式统一 | adapter 解码和对齐数据，同时记录最终质量行的准确时刻、各测量 topic 的有效读数时刻；B01 校验并输出统一契约。时间轴随行转换，不按消息数量或 stride 推算 |
| B02 全局统计 | 仍负责统计；现与 B01 共用格式转换和时间轴校验函数。未改变统计人口选择、数值拟合方法或缓存策略 |
| B03 质检判断 | 消费 B01 的测量时刻，与质量时间轴比较后应用缺测阈值；不再重新扫描 MCAP。保留原 S1–S4 与整条拒绝规则 |

“有效读数”是输入事实，不是质量通过：对本 profile 要求正确宽度字段且有限；物理上下限仍属于数值质量规则。空消息、缺字段和 NaN/Inf 不刷新测量时刻，也不单独令文件拒绝；若附近存在阈值内的有效读数，覆盖仍可通过。无法解码的结构损坏消息仍按输入错误处理。

`QualityEpisode` 增加 `valid_measurement_times_ns: dict[str, int64[N_topic]]`，放在原有字段之后，原有位置参数顺序保持不变。时间校验同时覆盖长度、非负 int64 范围和单调性，避免无符号差分回绕。

## 外部适配器必须接入的接口

提供以下方法，返回内容必须对应 `to_quality_arrays(standard)` 的**最终行顺序**：

```python
def to_quality_timeline(self, standard):
    return {
        "frame_times_ns": ...,  # int64[T]，真实的源时钟纳秒时间戳
        "valid_measurement_times_ns": {
            # 启用覆盖检测时，按其配置的 topic 名提供有效测量时刻。
            # 每个值为 int64[N_topic]，不必等于 T。
        },
    }
```

这段是接口形状，不是可以直接运行的实现。实际时间戳必须在 adapter 选择、过滤、对齐、降采样质量行的同一步保存，再传入 StandardEpisode 的元数据或等价字段。Jindian 的本地实现可参考 `adapter.py` 的 `load_raw()`、`to_standard_episode()` 和 `to_quality_timeline()`。

- 时间戳必须非负、非递减且可表示为 int64；不能返回秒、浮点数或重建的匀速时间轴。
- 使用 `log_time` 的质量行与测量读数必须使用同一源时钟。若 profile 用另一时钟，两者需保持一致。
- 空整数数组表示“确实没有有效测量”；缺失 topic 键表示“未提供该检测需要的元数据”，B03 按接口错误处理。
- ABC 当前关闭夹爪覆盖，可以返回空的 `valid_measurement_times_ns` 字典，但仍必须返回准确的 `frame_times_ns`。
- 若 ABC 质量转换会过滤或重排行，时间数组必须同步；不能把全部摄像头消息简单按数量匹配。该接口要在取得真实 ABC adapter 后接入，本次没有虚构其字段名或兼容行为。
- 旧 `reference_topics` 配置字段仍可解析，但 B01 不再用它重建时间轴；adapter 是最终质量行时间的唯一来源。
